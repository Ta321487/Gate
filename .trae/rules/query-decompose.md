# 提问拆片（控 token）

用户常「一事只问一句，但牵扯多域」。**不等用户手动拆**，助手收到消息后先拆再动工具。

## 何时必须拆

同一条消息里出现 **≥2 个可独立收工的交付**（例如：改代码 + 全量 pytest + 浏览器验收 + 交付审计 + 改 HANDOFF + 解释概念 + 提交 git），或 **≥2 个主链路段**（匹配 / bake / 基线 UI / 门禁 / 单包 / 论文材料），**第一回合禁止**按清单逐项全开。

## 第一回合（读文件 / 跑命令 / 改代码之前）

1. **主诉求一句**：用户这条最想拿走什么。
2. **拆片表**（最多 6 行）：`片名 | 答/改/验/写 | 本轮做否`。
3. **默认只执行标「本轮」的主片**；其余标「待你一句 / 下条消息」——用户写了「全做」「顺便都做」「别拆」则按用户来。
4. **修工厂 / 止血 / 问清** 仍按 `boss-intent` 表态，与拆片表同屏，不另写长报告。

## 主片优先级（冲突时用）

修共享根因 > 对口单测或单条门禁 > 口头解释 > 浏览器或 Playwright > 全表 layout smoke > 交付审计 > 大改 HANDOFF 或 docs > AOCI overview。

## 非主片的硬约束

- 禁止：`aoci_overview`、无必要的 HANDOFF  ritual、layout 全表 smoke、form-controls 全包扫、Playwright 扫学生包、medium+ explore 全仓。
- 用户已给路径、测试名或报错片段：禁止为「查全」再扩搜。
- 「只解释」片：结论优先，代码用 `path:行` 指针，不贴大段 cite。

## 收工

主片做完再简短列出 **余片 + 一句怎么接**（例如「下条说：做片 B」）。用户中途改口「先做 B」→ 重排表，已做的不重复读大上下文。

## 口令

| 口令 | 含义 |
|------|------|
| `全做` / `顺便都做` | 按拆片表顺序尽量做完（仍受 delivery-audit「只报告不改代码」等硬规则约束） |
| `主片_only` | 只做表内第一个「改/验」片，余片只列标题 |
| `别拆` / `别拆只答` | 不拆表，纯答疑，不动代码、不跑闸 |

## 惯例（本仓库 · 用户未另说时）

| 常一起出现的 | 默认拆成 | 主片（除非用户点名另一片） |
|--------------|----------|----------------------------|
| 门禁红 + 怎么修 | 解读 / 改工厂 | 有门禁名、traceback 或「修」→ **改工厂** |
| layout + form-controls | **两片** | **layout 先**（几何一票否决） |
| 看包 / 浏览器 + 修代码 | **两片** | 给了预览 URL → 主片=验；否则 **修工厂** |
| 交付审计 + 修 bug | **两片** | 说「审计/验收/report」→ 主片=**只报告**；说「修」→ 主片=修工厂 |
| 模块图 / 论文材料红 + bake | **两片** | 主片=材料闸（如 `modules.py` 清洗）；**不**夹带全厂重 bake |
| 解释概念 + 顺手改 | **两片** | 主片=**答**；改代码待一句「做片 B」 |
| 新对话 + 一堆未提交 diff | 读 git / 读 HANDOFF / 干活 | 主片=用户**本条**任务；HANDOFF **只读头段 + 与主片相关的「下一步」**，勿为余片通读 |

## 关于「自我学习」

项目规则**不会**跨会话自动改权重。你纠正拆法时，助手优先在本节 **惯例** 表补一行（或写入 Cursor User Rule）；改仓库规则后跑 `scripts/sync-ide-rules.ps1`。
