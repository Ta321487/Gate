本科毕业设计（论文）开题报告

题目：基于 Spring Boot 与 Vue 的学校行政印章使用申请审批系统的设计与实现

开题年份：2025
清单编号：P-01
挂靠领域：DOM-SEAL

一、选题背景与意义

1.1 选题背景
学校综合办、院系办公室日常用章仍多依赖纸质申请或口头报备，印章管理员难以掌握「谁在何时为何事用章」，事后台账不全，审计追溯困难。行政审批信息化要求下，需将用章申请、事项分类与审批留痕纳入同一套 Web 系统。

1.2 选题意义
（1）规范业务主流程并形成可查询台账；
（2）审批或确认过程留痕，便于管理核查；
（3）完成前后端分离的 Web 管理系统工程实践；
（4）支撑本科毕业设计答辩演示。

二、国内外研究现状

同类管理信息化产品在高校与企事业单位已有应用，商业方案常绑定硬件门禁、真支付或大型一体化平台。本科毕设定位为演示级 Web 管理系统，实现开题所述主路径即可，不追求生产级全链路对接。

三、研究目标与主要内容

3.1 研究目标
实现印章/用章事项建档、在线提交用章申请、管理员审批通过或驳回、申请记录查询及公告管理。

3.2 主要功能（拟实现）
1. 用户登录、个人资料与角色权限（申请人、综合办管理员等）；
2. 印章或用章事项档案维护与分类检索；
3. 提交用章申请（事由、份数、使用时间等）；
4. 管理端待办审批：通过、驳回与意见留痕；
5. 我的申请与全库用章记录查询；
6. 公告发布与须知阅读；

3.3 拟解决关键问题
（1）申请单状态流转清晰，禁止非法跳转；
（2）审批意见与操作人可追溯；

四、技术方案

后端采用 Spring Boot 构建 REST 接口；持久层可按开题选用 JdbcTemplate、MyBatis（PageHelper）或 Spring Data JPA 访问 MySQL。前端采用 Vue 3 与 Element Plus 搭建用户端与管理端页面，工作台可用 ECharts 展示统计图表。系统按表现层、业务层、数据访问层分层设计。若开题写明 Spring Security，则启用登录鉴权与过滤器链。

五、非本期范围

多级会签引擎、银行直连、电子签章 CA、硬件门禁不在本期。

六、进度安排

第 1–2 周：文献调研、需求梳理并完成开题答辩；
第 3–4 周：完成总体设计、数据库 ER 图与接口说明；
第 5–10 周：分模块编码实现核心业务与权限控制；
第 11–12 周：功能测试、缺陷修复与演示数据准备；
第 13–16 周：撰写毕业论文、整理答辩 PPT 与操作说明。

七、预期成果

（1）可本地部署运行的 Web 管理系统；
（2）MySQL 建表脚本与示例数据；
（3）符合学院规范的本科毕业论文一份；
（4）系统演示说明或答辩材料。
