> **工厂原则**：开题题型不可预判，缺口按**全覆盖**入册；本清单内条目均为待补交付，不按「做 / 不做」取舍。

> **本文后半（§13 起）**：少踩坑——依赖、状态审计、验收开题句、反模式、文案落点；先读再改代码。  
> **标已齐 / 做审计**：必须另按 [`delivery-audit-rules.md`](./delivery-audit-rules.md)（七层、硬闸、新×旧、落得准、论文图、字段语义）。

## 0. 怎么用这份文档

| 列 | 含义 |
|----|------|
| **ID** | 稳定编号，实现与测试可引用 |
| **落点** | 深皮 = 扩现有 DOM；新预设 = 新薄 `DOM-*` / preset；新能力 = 新运行时玩法 |
| **挂靠 / 近邻** | 今日误落或将来挂靠的域 |

**阅读顺序（防坑）**：§2 易混对 → §13 反模式 → §15 依赖 → 再动对应 `S/P/C`。

**非本清单（硬边界，不是缺口）**：见 §8。人脸、真支付、小程序原生、物联网、硕博真全流程等仍按现网 reject / out_of_mvp，不计入「换皮全覆盖」。

## 14. 状态审计口径（回写「待补 / 部分有 / 已齐」）

**先审计再开发。** 只对照现网，改本文状态列；审计轮不新增 DOM。

### 14.1 判定标准

| 状态 | 必须同时满足 |
|------|----------------|
| **已齐** | ① 开题句稳定命中目标 DOM/交叉；② bake 主流程可走通；③ §2 相关易混对不互抢；④ 有样例开题路径；⑤ 学生可见文案不穿帮（菜单/种子/身份） |
| **部分有** | 引擎与域已在，但词表/场景/种子/样例/易混 任一缺口导致偶发误匹配或客户误读 |
| **待补** | 无具名落点，或主流程无法演示，或仅 GENERIC 顶替 |

### 14.2 审计检查清单（逐 ID）

对每个 `S-*` / `P-*` / `C-*`：

1. **catalog**：是否有 keywords / match_hint 覆盖该题型说法？  
2. **样例**：`data/samples/`（含 `域开题样例近五年/`）是否已有可上传文本？  
3. **场景**：校园/企业/社区是否需要分档？有则 `scene_scan` 是否已覆盖？  
4. **种子**：演示账号下列表是否会引发「我的=多家」类误读？

## 18. 种子与 UI 语义公约（少踩「我以为是…」）

适用于所有 archive 列表型用户页（跟进/报名/借用等）：

1. **菜单名与数据范围一致**：「我的 X」⇒ 当前用户关联集合；全库浏览⇒「X 检索 / X 目录」。  
2. **演示账号默认故事**：一个主角 + 少量关联对象；需要多条样例时，用不同账号或文案标明「示范数据」。  
3. **状态标签诚实**：「实习中 / 在借 / 已报名」只打在真实关联关系上，不要给目录项统一打「进行中」。  
4. **主按钮动词 = 真实动作**：提交周报 / 借阅 / 报名 / 投递，禁止用「进入单位」这类入职隐喻，除非域真是入职流。  
5. **hero 与侧栏同一叙事**：banner「提交周报」与菜单「岗位目录」须能互相解释（已按 §18 改名，禁止再写「我的实习岗」却列全库）。  

INTERN 是样板坑（M-01，已齐）；修其它深皮时同一公约套用。
