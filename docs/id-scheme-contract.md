## 0. 为何单独立册

运营侧与学生包管理端都能看到「一串号」，但来源不是一类东西：

- 有的是**行主键**（自增），列表几乎不当主文案；  
- 有的是**工厂业务键 / 目录码**（`gf-…`、`DOM-*`、`cap_id`）；  
- 有的是**给人念的业务号**（证明流水号、取票码、核销码）。

现状像「各种风格」，主因是**分层没写死**，不是缺一个万能 UUID。  
**裁定**：要整理；**禁止**一种格式打天下；**禁止**为大整齐迁已有项目 id / 已 bake 包旧单号。

## 1. 三层合同（核心）

| 层 | 名称 | 落哪 | 给人看？ | 现行口径（待定锁定） |
|----|------|------|----------|----------------------|
| **A** | 机器行键 | 工厂库 / 学生库表 `id` | 默认可藏；调试偶见 | `INTEGER` / `BIGINT AUTO_INCREMENT`；控制台列表**不以**它当主展示文案 |
| **B** | 工厂业务键 · 目录码 | 工厂库 / 匹配确认 / 资产台 UK | **运营日常对的就是这些** | 见 §2 |
| **C** | 给人看的业务号 | 学生库业务列（非技术 PK） | **管理端 / 用户端 / 答辩会念** | 见 §3；**新号只走共享签发家**（开工后） |

另册、**不进本册收口**：论文图 / 用例图节点 id（如 `prefix_uuid`）、布局 pattern id、主题色 swatch id——那是材料几何键，不是运营单号。

## 2. B 层 · 工厂业务键（文档化，不大迁）

| 种类 | 现行形状 | 待定裁定 |
|------|----------|----------|
| 项目 id | `gf-YYYYMMDD-HHMMSS`（撞秒可加后缀） | **保持**可读可排序；禁止改成纯 uuid 当唯一对外号 |
| 临时方案 / 计划 | `gf-plan-{uuid12}` | **保持**；勿再发明第三种 `gf-*` 变体 |
| Job / LLM 调用行 | 自增 int | 属 A；API 可返回，运营文案跟项目 id |
| 资产台行 | 自增 `id` + 业务 UK（`domain_id`×`machine_id`×… / `cap_id` / `kind`×`key_name`…） | **保持**双键；侧栏主展示跟业务 UK / 中文，不跟自增 |
| 目录码 | `DOM-*`、能力 / 开关 / `machine_id` / addon | **只增不改风格**；新码跟现网表，不开平行命名空间 |

**明确不做**：把 `DOM-SHOP` 改成别的前缀体系；批量改写历史 `projects.id`。

## 3. C 层 · 学生包可见业务号（真伤 · 开工优先）

### 3.1 现状抽样（风格分裂点）

| 列 / 语义 | 现行签发（基线） | 问题感 |
|-----------|------------------|--------|
| `cert_issue_no` | `CERT` + 8 位（`nanoTime`） | 前缀有语义；熵源散落 |
| `pickup_redeem_code` | `PK` + 10 位（`nanoTime`） | 同上 |
| `pickup_code`（影院等） | `orderId % 10000` 四位 | 与 CERT/PK 完全另一套 |
| 席位会员码等 | `M` + 5 位 `Math.random` | 随机、难复现测 |
| 数字商品码 | `PERMIT-{id}-{uuid8}` / `ACT-{uuid10}` | 又一套 |
| 订单短 token | UUID 截 8 位大写 | 又一套 |
| 外单号（快递 / 物流） | **手填** | **正确**：不进签发器 |

以上仅盘点；**待定阶段不改行为**。

### 3.2 待定目标口径（开工后才执行）

1. **共享签发家**（建议落点：基线一处 Java util + 工厂侧若有种子号则同规则说明；三套 Store 不各写一套）。  
2. 形状：`{短前缀}{定长正文}`；前缀表按能力/域语义维护（`CERT` / `PK` / …），**正文只许一种生成策略**（单调序或时间序；**禁**再散落 `nanoTime` / `Math.random`）。  
3. 长度、字符集（数字 / 大写）进表 + 单测；换开题仍同家。  
4. **外单号**（`tracking_no` / `express_no` / 用户粘贴的承运号）永远手填，不进签发家。  
5. 技术 PK（订单 `id` BIGINT）继续自增；可见号是**另一列**，禁止拿自增冒充「单号规则已齐」却无展示列。

### 3.3 不做

- 为整齐把已交付包里的旧流水号批量重写。  
- 为「统一」删掉有业务含义的前缀（证明流水 ≠ 领取核销 ≠ 真伪查询）。  
- 只擦当面学生 ZIP。
