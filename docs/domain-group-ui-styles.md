## 0. 硬口径

### 0.1 与加厚的分工

| 层 | 文档 / 模块 | 何时做 |
|----|-------------|--------|
| 能力四件套 | 地图 §1.x + `*_thicken` | 先做；本组待补清零或 batch 收口 |
| **本册：页内构图** | §2 · `{组}_surface_style` | **加厚后**再开该组独立实现 plan；已接线的键不动 |
| **本册：壳** | §3 | 页内构图归 §2，壳归本节。配色角色写在壳里；本轮只记规矩 |
| 字体 | 不单列 | 正交，不绑本册 |
| 门户首页 | `portal_home_style`（cards / editorial / mall） | 正交；交易 mall 已有，不重做 |

### 0.2 菜单保全（毕设 + 论文）

换构图只改**页内排列与信息密度**，不删、不藏、不合并交付菜单与路由入口。

- 匹配挂上的用户端 / 管理端 / 员工端菜单须仍可从壳导航点进。
- 首页构图（editorial / mall 等）不得取消侧栏或顶栏里已有业务入口。
- 禁止为了「像内容站 / 商城」做成单页沉浸、管理功能只留深链。
- 能力未挂而不出的菜单仍按 cap / 扫词，不在此列。
- 答辩截图与论文插图依赖「菜单还在、点得到」。

### 0.3 选型键命名（统一，禁止混用 browse）

| 层 | 规则 | 例 |

### 0.4 一组一实现 plan（禁止跨组一轮做完）

| 字段 | 内容 |
|------|------|
| 触发 | 该组 thicken 已收口，或地图本组待补已清 |

## 3. 壳

和 §2 页内构图并列。§2 管页里面像不像书架、货架、号源条；本节管外面那层壳。老师说「应付」，指的是顶栏一长串、Element 默认蓝、个人中心一整张表、封面用表情、横幅点进去不是这张配的记录。这些原来不归本册。

**本轮只记规矩。** 不改 `{组}_surface_style`，不改 bake、骨架、学生包。对标若不适合作答辩，标在该组，等老板否；否掉之前不按该产品改代码。

旧 DOM-SHOP 农产商城包是交易组的样板，只证明壳能收成下面这套。农产绿、水果文案、右侧栏那九项具体名单、模拟充值，都是商城皮，不写进别的组。

工厂现状（待以后改骨架，本节先钉住）：`navOverflow.js` 不超过 12 项就全铺在顶上，再多才收进「更多」。8～11 项的下拉已经不像产品。首页轮播只取第一张有图的横幅。列表「查看」常以抽屉交差。个人中心常是整张档案表。种子封面仍有表情图。

### 3.0 九组共用

主路径是这条开题匹配到的业务链，不是对标 App 的底栏。商城开题写了购物车和下单，主路径就是浏览、加购、下单；影院开题是排片选座，没有购物车这条主路径。开题写到、匹配挂上的菜单必须还在、点得到，和 §0.2、各组菜单保全同一条。对标页没有的功能，开题写了也不能删。对标页有、开题没写的，也不能为了像它加上。

顶栏只放这条主路径上的少数入口，大约四五个，用该业务自己的说法。禁止不满 12 项就全铺。开题写到的菜单必须还能点到。多出来的功能放哪，按本组的壳，见 G-3.1～G-3.9。悬停打开、点一下钉住、屏幕中间勾选、顺序记在本机，只留给交易组那种右侧图标栏，别的组不套。禁止把主路径收进个人中心，换一条看起来短的顶栏。

老师说的「糊弄」是一眼看上去：像一套没人收拾过的 Element 后台。补农产才把这个印象落成具体洞：顶栏八到十一项仍全铺、选中的行业配色盖不住 Element 默认蓝、个人中心一整张表、封面用表情、横幅只取第一张且点进去不是这张配的记录、列表用抽屉交差、管理端品牌条深字和「后台管理系统」。促销珊瑚是那一单手选的，不是工厂默认。这两层不要并成一句「像不像开题」。

顶栏具体留哪几项，跟这包开题已经挂上的菜单走，不另写一份死名单，也不抄农产右侧那九项。叮咚底栏、超星把借阅放进个人中心，只说明公开页可以短，不决定桌面顶栏的按钮名。已定的是：开题菜单还在；顶栏不要铺满；多出来的功能按本组摆法收。
