# 开题密功能 → 工厂交付对照表

> **用途**：接单 / 匹配 / bake 时查「开题写了啥、工厂落哪、别踢错壳」。  
> **搭配**：主链路 [`delivery-audit-rules.md`](./delivery-audit-rules.md)；缺口立项 [`domain-skin-gap-analysis.md`](./domain-skin-gap-analysis.md)；AI 专项 [`ai-opening-delivery-map.md`](./ai-opening-delivery-map.md)；域表 [`HANDOFF.md`](../HANDOFF.md)。  
> **素材**：近约十年国内本科毕设/课题常见模块（商城、助农、点餐外卖、预约、报修、借阅、活动、论坛等公开选题与功能表）+ 工厂现网能力。  
> **不是**：真实世界业务全集。表是活的——撞到新高频点就加行；缺口进 gap 册立项。

**状态列**：`有` = 现网可交 · `扫词开` = 命中才挂 · `演示` = 能演示勿吹真系统 · `不做` = 硬边界 · `缺口` = 未齐待立项

**匹配列**：附属功能勿抬成第二主路径 / 勿降 `DOM-GENERIC`（代码：`catalog.reconcile_match` soft 规则）。

## 8. 怎么用（少人工）

1. **匹配**：密开题先落对 `DOM-*`；附属审核/库存等走 soft，禁止无故 `DOM-GENERIC`。  
2. **挂载**：表内 `扫词开` 命中则开；`演示` 论文按实包写；`不做` 匹配页提示。  
3. **缺口**：`缺口`/`部分有` → 写入 [`domain-skin-gap-analysis.md`](./domain-skin-gap-analysis.md) 再立项。  
4. **回归**：`tests/test_shop_marketplace.py` 等假开题；改匹配必跑。  
5. **扩表**：网上/接单再出现高频模块 → 加行，不改开题迁就工厂。
