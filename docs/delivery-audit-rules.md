## 1. 工厂在干什么

从**开题报告 / 任务书等材料**认出要做哪类业务系统 → **关键词硬分流 + Match Agent 长尾**落到具名域 → **bake 出可答辩 ZIP**。

出包必须齐（跟材料一致，不是空菜单）：

| 块 | 要有什么 |
|----|----------|
| 匹配 | 题名/正文能落到正确 `DOM-*`，不抢邻域旧题 |
| 业务逻辑 | 主流程（如选档案→申请→审→完结）真可走 |
| 状态机 | 状态集合、合法转移、谁可点、按钮文案一致 |
| 登录与身份 | 登录页氛围 + 注册/资料身份跟场景（校园/企业…） |
| 前台 / 管理端 | 列表、提交、待审、记录等页面跟域皮 |
| 数据 | SQL 表与种子能演示主路径（约 6～15 表） |
| 说明书与论文图 | README / ER / 模块图 / 用例与**实包**一致 |

**开题优先**（工厂已能 bake 时跟开题）；开题未写清 → 用该域工厂默认。  
**禁止**改开题迁就工厂；禁止宣称有却缺表/API/规则/状态机/字段（空壳）。

匹配口径：词表只做**硬分流**（预算内关键词）；开题近义/变形交给 **`match_recommend`**，不要为每簇另写专扫、也不要无限堆近义词。

### 1.1 「常见好做」默认实现 ≠ 材料未写硬加

| | **默认做** | **可不做** |
|--|-----------|-----------|
| 判据 | 答辩常见、实现成本低、有时间/额度/布局等字段就能挂规则 | 开题/任务书等材料未写，且非主路径必需 |
| 例子 | 过开场/过出发自动下架；座位排×列可配；影厅类型/厅名/开场时间分栏；过截止拒报名；过期时段不可再约；借还逾期推进 | 真支付/地图导航/人脸/物联网；材料未提的复杂算法、硬件、外部对接 |
| 禁止 | 为「图省事」把两业务概念糊进一个备注字段、或故意砍掉已有时间列上的简单规则 | 用「材料没写」当借口砍掉上表「默认做」类逻辑 |

审交付时：发现「省过头」→ 标**部分有**或空壳风险（视是否假宣称）；材料明确只要更窄主路径且未宣称高级能力 → 可记「材料未要求」而非硬缺陷。

## 2. 场景轴 ≠ 技术栈轴

| 轴 | 干什么 | 别混 |
|----|--------|------|
| 场景 / 身份 | `scene_scan` → 壳文案、资料字段、岗位名 | 勿在 profile / builders 另写一套 hint |
| 技术栈 | `spine` / `persistence` / `spring_security` | 不替代领域；开题写了且能 bake → 跟开题 |
| `ARCH-*` | 能力路径 | **不是** Boot+Vue / SSR |

详见 `.cursor/rules/opening-scene.mdc`、`tech-stack-delivery.mdc`。

## 3. 审交付：盯红灯（够用就停）

审计轮**默认只出报告、不改代码**（人明确下令才改）。  
清单标「已齐」≠本轮通过。

### 3.1 必问（老板小卡，缺一条报告无效）

| # | 问题 |
|---|------|
| 1 | 有没有**空壳**？ |
| 2 | **旧题**（至少图书 / 宿舍 / 实习）回归红了吗？ |
| 3 | **状态机**对且准吗（集合/转移/角色/文案）？ |
| 4 | **字段**用户可见含义像本题吗（有没有壳字段穿帮）？ |
| 5 | 客户会不会**看错主流程**（「我的」/种子/按钮诱导成借用或报修）？ |
| 6 | 新域有没有**抢走旧题**匹配？ |
| 7 | 学生可见面有没有「**演示**」字样？ |
| 8 | **开题有没有被改**来迁就工厂？ |
| 9 | 该 **reject** 的硬边界还拒不拒？ |
| 10 | **论文图**（ER/模块/用例）跟实包一致吗？ |
| 11 | **皮肤/布局**选项进包生效了吗？ |
| 12 | 登录氛围与门户轮播是否分套、身份是否跟场景？ |

### 3.2 四级

| 级 | 何时用 |
|----|--------|
| **已齐** | 主链路齐、红灯全绿、未伤旧 |
| **部分有** | 引擎在，有洞，但不构成对外假支持 |
| **待补** | 无具名落点或主路径不存在 |
| **空壳风险** | 宣称有，内里缺一截 |

### 3.3 报告怎么写（短）

1. **总表**：域/ID → 四级 → 一句话  
2. **红灯**：空壳 / 状态机 / 字段 / 匹配互抢 /「演示」命中（路径+原文）  
3. **旧题回归**：图书、宿舍、实习（+本轮邻域）  
4. **老板小卡** 12 条是/否  
5. 本轮是否改代码（默认否）

不要为凑章节写十四节空话；人侧只看总表+红灯+小卡。

### 3.4 组审纪律

按业务组收口。组内域未审完，**禁止**开下一业务组。  
已验进度写在交接或报告里，勿只改清单计数假装收口。

| 组 | 状态（2026-08-04） |
|----|-------------------|
| **借用 / 占用**（HANDOFF 组 A + 收口簇 CINEMA，47 域） | **已收口**（H23 + 档案列契约；详见清单册进度节） |
| **报修 / 工单**（DORM / PROPERTY / IT） | **当前**（可开审） |
| 报名 / 交易 / … | 报修组收口前禁止开 |

## 4. 红灯细则（压缩表）

| ID | 项 |
|----|-----|
| H23 | **常见好做**：有时间/布局/额度字段时，简单规则默认实现；禁止两概念糊一备注、禁止刻意砍过期下架等（§1.1） |
| H20 | 字段可见含义像本题（内部 key 可通用，**label 必须域皮**） |
| H21 | 状态机：集合/转移/角色/文案与 Store、前端一致 |
| H22 | 学生 ZIP 可见面无「演示」（注释/工厂 docs 可豁免） |
| H08 | 零命中禁止误落 LIBRARY |
| H06 | 前端禁止用 `DOM-*` 做业务分支（用 flavor/traits） |
| H01/H19 | ER/模块图/用例跟交付 SQL 与 menus |
| H12 | 禁止 degraded 装全文；未挂能力不得宣称 |

落得准（抽检即可）：新题正句→新域；旧题仍旧域；主路径匹配→bake→可点；「我的」与列表范围一致。

**硬边界（期望拒）**：人脸/真支付/小程序原生/物联网真开锁/道闸抬杆·车牌识别硬件/GPS 轨迹考勤/银行医保疾控直连/三主路径以上智慧校园等——见 HANDOFF / `OUT_OF_SCOPE_SIGNALS`。诚实说法用不含「演示」的措辞（如「非真支付」「本期无银行打款」「非真门禁」）。

## 5. 改代码时对照

| 要改 | 常见落点 |
|------|----------|
| 域 / 关键词 / hint | `domains_catalog/*.py` |
| 申请/跟进皮 | `schema/*_presets.py`、builders |
| 场景身份 | `scene_scan.py`、`profile_fields`、种子 SQL |
| 匹配长尾 | `match_recommend`（勿另开域专扫） |
| 能力 / 门禁 | capabilities、基线 Store、gate |
| 清单状态 | `domain-skin-gap-analysis.md` |

伤旧或落不准 → **不得**标已齐。

## 6. Agent 套话

```
按 docs/delivery-audit-rules.md：只出报告不改代码（除非下令）。
交付物：总表 + 红灯 + 旧题回归 + 老板小卡 12 条。
范围：<域或清单 ID>。盯空壳、状态机、字段皮、匹配互抢、学生可见「演示」。
```

```
按 docs/delivery-audit-rules.md 主链路落地；开题优先；不得伤旧题。
对照 domain-skin-gap-analysis.md 的 <ID>；标已齐前红灯全绿。
```
