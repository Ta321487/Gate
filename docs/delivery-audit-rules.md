# 工厂交付审计规矩（Agent 依据）

> **地位**：凡「审交付 / 标已齐 / 落地新域或新能力 / 声称全覆盖完成」的 Agent **必须按本文执行**。  
> **配套**：待办册见 [`domain-skin-gap-analysis.md`](./domain-skin-gap-analysis.md)；能力与域清单见 [`HANDOFF.md`](../HANDOFF.md)。  
> **版本**：v4.3（2026-07-27）。新坑 **只追加** H/L/小卡编号，不删既有项。

## 老板小卡（人只看这 12 条）

Agent 出具的审计报告 **必须代填**下列是/否。缺任一条 → **整份报告无效，退回重做**。

| # | 问题 |
|---|------|
| 1 | 有没有 **空壳**（宣称有，表/API/规则/皮肤/字段/状态机缺）？ |
| 2 | **旧题回归**红了没有（默认图书 / 宿舍 / 实习）？ |
| 3 | **硬闸**（H01–H22）红了没有？ |
| 4 | **新域有没有抢走旧题**匹配？ |
| 5 | 客户会不会 **看错主流程**（文案/种子/「我的」）？ |
| 6 | **开题有没有被改**来迁就工厂？ |
| 7 | **皮肤/布局**抽检过没有（选项是否进包生效）？ |
| 8 | 该 **reject 的硬边界**还拒不拒？ |
| 9 | **论文 ER / 模块图 / 用例表**是否与实包一致？ |
| 10 | **字段含义**是否像本题（有没有壳字段穿帮）？ |
| 11 | **状态机**是否对且准、符合本题流程（转移/角色/文案一致）？ |
| 12 | 学生包可见面有没有 **「演示」字样**（命中须列清单；默认不得留）？ |

人侧日常只审本表红灯；不要求通读 diff。

## 0. 前言（执行必读）

| 原则 | 含义 |
|------|------|
| 工厂大而全 | 题型须有具名落点；禁止长期 GENERIC/空壳顶替清单项 |
| 单题跟材料 | 业务细则由开题/任务书定；写清且能 bake → 跟开题；未写清 → 工厂域默认 |
| 落得准 | **新题对新落点通**，且 **旧题不被带偏** |
| 实包一致 | 实包 = 学生 README = 论文「系统实现」表述；未实现名词禁止出现 |
| 审计默认 | **只出报告、不改代码**；用户明确下令后才改 |
| 与清单关系 | 本文验「做了没、准不准、伤没伤旧」；缺口册是待办 ID；伤旧或落不准 → **不得**把清单标已齐 |

禁止：改开题迁就工厂；错域冒充；degraded 装全文；能力未挂却宣称支持。

## 1. 七层（「已齐」必须全过）

| # | 层 | 审什么 | 不合格示例 |
|---|----|--------|------------|
| 1 | **业务规则** | 主流程、角色、名额/归还/占坑等与该类开题叙事一致 | 周报壳跑成投递规则 |
| 1b | **状态机** | 状态集合、合法转移、谁可点、标签文案与本题流程一致；前后端/Store 同一套 | 借阅题用报修状态；可跳非法转移；按钮有转移无 |
| 2 | **表** | 档案/单据/lookup 映射、种子、库表 6～15、`domain_entities` 真源 | 表名串域；无种子主路径 |
| 3 | **API** | 列表/提交/审单等真实存在且与前端一致；门禁能验 | 空 Store；调不通 |
| 4 | **文案与身份** | 菜单/按钮/状态/须知/README；`scene_scan` 与 profile 同源 | 「我的 X」实为全库；企业题学号 |
| 4b | **字段语义** | 档案列、工单列、资料字段的 **用户可见含义** 像本题 | 实习题仍「ISBN/作者/在架」语义 |
| 5 | **皮肤与 UI 布局** | theme/flavor/traits；chrome/layout/typeface 进包生效；登录图≠门户轮播；无前端 `DOM-*` 业务分支 | 选题皮肤；布局选项无效 |
| 6 | **匹配与硬边界** | 正命中/易混不抢；L3/超壳/三合一仍拒；错皮可拦 | 假 full；错皮放行 |
| 7 | **论文材料** | ER↔交付 SQL；模块图↔menus；用例表↔menus/roles；中文标签 | 图有包无、包有图无、开题虚构功能 |

- 缺一层 → 最高标 **部分有**。  
- 对外宣称有，却缺表/API/规则/皮肤/字段/状态机/论文图 → **空壳风险**（优先打出）。

### 1.0 状态机细则（1b）

| 看什么 | 准 | 不准 |
|--------|----|------|
| 状态集合 | 与本题流程一致（如待审阅/已通过/退回；待审/初审/终审等） | 串用别域状态词或多余/缺失主状态 |
| 合法转移 | 仅允许流程上的边（提交→待审→通过/驳回…） | 前端能点、后端拒；或后端默许非法跳转 |
| 角色权限 | 谁提交/谁审/终审是否总管等与 schema、开题一致 | 实习生能终审；子管越权 |
| 可见文案 | 状态 label、按钮动词与转移一致 | 按钮写「导师通过」实际无该转移 |
| 实现一致 | `ticket_rules` / Store / 前端禁用逻辑同一套 | schema 一套、Java 另一套 |
| 二级审批等 | 域或开题要求开启时，`pending→pending_final→approved` 等真在 | 文案有「二级审」、状态机仍单级 |

抽检：schema `states`/`verbs`、相关 Store 转移、用户端与管理端按钮、README 主流程段。对照 `ticket_rules.py`、TicketStore、域 preset。

### 1.1 字段语义细则（4b）

| 看什么 | 准 | 不准 |
|--------|----|------|
| 列表/表单/详情/导出可见列 | 标签与本题实体一致 | 壳域字段语义裸奔 |
| 内部 key | 可通用（如 title/author 映射） | **label** 必须域皮 |
| 状态/分类/类型字典 | 本题用语 | 串台状态词 |
| 与 ER 中文 | 同一套含义 | 页与图不一致 |

抽检：`domain-*-columns` / schema fields / 页面 / 导出表头。

### 1.2 论文材料细则（层 7）

| 产物 | 必须对齐 | 不准 |
|------|----------|------|
| E-R | 本包交付 SQL + 中文实体（`er_zh` 等） | 多表少表；串域实体名；无中文 |
| 功能模块图 | 本包 menus（按业务/按端与工厂选项一致） | 开题有菜单无；菜单有图无 |
| 软件测试用例表 | menus/roles 推导 | LLM 发明功能/增删用例越权 |

开题只辅助命名，**不得**画与 ZIP 无关的虚构结构。

### 1.3 「演示」字样细则

学生交付物（ZIP 内前端可见文案、公告/须知种子、学生 README、论文材料页生成文案）**默认不得出现「演示」**，避免答辩包看起来像玩具/临时系统。

| 范围 | 要求 |
|------|------|
| 必扫 | `skeletons/baseline/frontend`（及 bake 后学生包）`.vue`/`.js` 用户可见字符串；SQL 种子公告；生成 README；论文图旁说明 |
| 不准 | 「演示系统」「仅供演示」「演示数据」「（演示）」「演示码」「演示余额」等可见字样 |
| 诚实边界（用不含「演示」的说法） | 未接真支付 → 「非真支付」/「账户余额」；未接真门禁 → 「非真门禁」/「通行凭证」 |
| 可豁免 | 代码注释、工厂运营端、本仓库 `docs/`/`HANDOFF`、测试夹具；**不进学生 ZIP 的除外** |
| 报告 | 必须列出全部学生可见命中路径+原文；零命中才算本项通过 |

有命中且未清零、未获用户书面豁免 → **H22 失败**，不得标已齐。

## 3. 新×旧不打架（报告必有一节）

### 3.1 打架类型

| 类型 | 看法 |
|------|------|
| 匹配互抢 | 旧题正句是否仍落旧域 |
| 共享壳串台 | Order/Ticket 文案、traits、全局标签 |
| SQL/golden 污染 | 旧域 SQL golden、compose |
| Store/门禁/状态机膨胀 | 旧域转移边或状态文案被带偏 |
| 能力默认扩散 | 旧域多出 dm/recommend/任命等 |
| 全局皮肤/布局 | 基线 CSS / layout 改坏旧题 |
| 字段壳回流 | 旧域可见列被新改动污染 |

### 3.2 必跑

- 错皮矩阵（如 `test_domain_skin_leak`）  
- 相关 golden  
- 固定老题回归：**图书、宿舍、实习**（可加食堂/商城）  
- 若改动共享点（如 `TicketStore`、`catalog.py`、`themes.css`、`reconcile_match`、`fragments.py`）→ 报告写 **影响面** 并加抽旧域  

**判定**：新域绿、旧域红 → **阻塞**；新域 **不得**标已齐。

## 4. 落得准（报告必有一节，L1–L11 勾选）

| ID | 条件 |
|----|------|
| L1 | 新题正句 → 目标新落点 |
| L2 | 旧题正句 → 仍旧落点（反句不互抢） |
| L3 | 新域主路径：匹配 → bake → 门禁 → 可点通 |
| L4 | 新能力默认不扩散（材料命中才挂，除非域契约本就默认） |
| L5 | 表/实体走真源，不借用错域表语义 |
| L6 | 皮肤/布局：新旧包至少各抽 1 个验证生效 |
| L7 | 文案不诱导错流程（「我的」与列表范围一致等） |
| L8 | 论文材料：新域+旧域各抽 1 包核 ER/模块图/用例 |
| L9 | 字段语义：新域+旧域各抽列表/表单可见列 |
| L10 | 状态机：主路径转移可走通；非法转移不可走；状态文案像本题 |
| L11 | 「演示」字样：学生可见面零命中（或仅剩已豁免项且报告写明） |

L1–L3 任一失败 → **落不准**；禁止仅以「已加文件」冒充完成。L10 / L11 失败 → 不得标已齐。

## 5. 四级结论

| 级 | 条件 |
|----|------|
| **已齐** | 七层（含 1b/1.3）+ 相关硬闸 + 落得准 L1–L11 + 未伤旧 |
| **部分有** | 引擎在，有洞，但不构成对外假支持 |
| **待补** | 无具名落点或主路径不存在 |
| **空壳风险** | 帮助/catalog/文案/论文材料宣称有，内里缺一截（含状态机只改了文案未改转移） |

另标：**阻塞**（旧题/硬闸致命失败）/ **建议**（不阻塞）。

回写 `domain-skin-gap-analysis.md` 状态时遵守上表；空壳风险与阻塞优先于「文件已合并」。

## 6. 报告目录（缺一节整份退回）

## 8. 抽样策略

## 9. 场景与技术栈（审计时勿混轴）

- **场景/身份**：只认 `scene_scan`；与 profile/壳文案一致（见 `.cursor/rules/opening-scene.mdc`）。  
- **技术栈**：`spine` / `persistence` / `spring_security` 为另一轴；拟选≠可出包须双显；门禁按栈分支（见 `.cursor/rules/tech-stack-delivery.mdc`）。  
- **ARCH-***：能力路径，禁止用来表达技术主线。  
- 技术栈变更 **不得**改变场景身份判定。

---

## 10. 硬边界（不是缺口，期望拒或裁）

人脸/指纹/真闸机、真微信支付支付宝、小程序/原生 App、物联网真开锁、GPS 轨迹考勤、协同过滤深度训练、疾控/医保/银行直连、智慧校园 N 合一/三主路径以上、硕博真实全流程等 → 见 `OUT_OF_SCOPE_SIGNALS` / HANDOFF；审计期望 **reject 或明确非 full**，禁止假包。

演示级替代（若清单已收）须真有生成路径，不得仅靠文案。

---

## 11. 追加规则（防以后再漏）

1. 线上/客户新坑 → 追加 `Hxx` 或易混句，并尽量落测试。  
2. 不删除旧 H/L；作废则标「废止」并指向替代 ID。  
3. 老板小卡只增不减语义；若增第 13 条，同步改「缺节退回」计数。  
4. 本文与缺口清单冲突时：**更严者优先**，并开任务改另一份文档对齐。
