## 0. 硬口径（写代码前先背）

### 0.1 挂载：材料命中才 bake，否则保持域默认

| 规则 | 含义 |
|------|------|
| **默认关** | 本批新能力 **一律**「开题/任务书等材料写到才挂」；材料未写 → 包内无菜单、无表种子、无按钮、无 README 段落 |
| **扫词挂** | 词表进 `features/*.py`（或既有 soft scan），与 `coupon` / `order_review` / `guestbook` 同口径 |
| **禁止域默认硬塞** | 不得因「图书域常见」就把续借做成 LIBRARY 永远开；未写续借的图书题仍只走借还催还 |
| **例外（本批无）** | 若某能力被定为某域主路径刚需，须在本文单独开「域默认」行并写清理由；本批 **全部扫词开** |

### 0.2 文档 = 实包（禁止空壳宣称）

| 规则 | 含义 |
|------|------|
| **表写「已实现」** | 必须有 Store/API/菜单或壳附带路径，bake 可点 |
| **表写「扫词开」** | 命中材料 → 同上；未命中 → 包内不出现 |
| **禁止** | FAQ / README / 密功能表 / 论文系统实现写了功能，实包没有 |
| **本批启动时** | 先修历史超前宣称（§2），再落新能力；修完前不得标「已齐」 |

### 0.3 学生 ZIP 可见面：禁止「演示」话术

| 允许（工厂内部） | 禁止进学生包 |
|------------------|--------------|
| 工厂 docs、`HANDOFF`、`capabilities` 内部 desc、注释、测试名 | README、菜单、按钮、页面文案、须知、种子公告正文、论文「系统实现」、学生可见 FAQ 正文 |
| 门禁扫「演示」字样（既有 `semantic` 红灯 H22） | 「演示级」「演示码」「演示余额」「本期演示」「非真××演示」等打发语 |

**学生包诚实替代措辞**（写进 README / FAQ 时用）：

| 勿写 | 改写为 |
|------|--------|
| 演示通行码 | 通行码（系统签发；不对接闸机硬件） |
| 演示余额 / 演示支付 | 账户余额 / 系统内支付（支付密码校验；不对接微信支付宝商户） |
| 演示物流 | 物流进度（按订单状态生成节点；不对接快递公司接口） |
| 演示级库存 | 库存扣减与回补（单仓） |
| 本期演示范围外 | 本期不包含××（如闸机联动、银企直连） |

工厂内部仍可用「基线替代 / 加价边界」区分真 SDK；**不得**把「演示」二字打进 ZIP 可见面。

### 0.4 本批不做（继续硬边界 / out_of_mvp）

仅下列保持 **不支持**（密功能表须标「不支持」并写原因；禁止已实现/扫词开冒充）：

| 边界 | 原因（专本科/课设） |
|------|---------------------|
| 公海池 / 外呼中心 | CRM 重运营，非毕设舒适区 |
| 多仓调拨 / 多仓 WMS / RFID 全链路盘点 | ERP 级 |
| 完整 SKU 多规格矩阵（色×码独立库存） | 独立库存引擎；加价边界 |
| 高并发秒杀引擎 | 同上量级 |
| BPMN / 智能排课 / 复杂绩点引擎 | 过重 |
| 叫号大屏、道闸/人脸、真短信邮件、电子发票、地图 SDK、OCR、协同过滤、真支付商户清算 | 硬件/真通道/模型 |

**除此以外**：密功能表或 FAQ 里曾写过、且属专本科可复现的功能点 → **本批必须落地**（提到就挂），不得用「改文档删掉」搪塞。

### 0.4a 本批覆盖边界（答「是否全覆盖」）

| 已覆盖 | 不在本批「全覆盖」内 |
|--------|---------------------|
| §1 全部 E-01～E-14 + DOC-FIX/COPY/MAP | §0.4 硬边界 / out_of_mvp（公海、多仓、完整 SKU…） |
| 密功能表里曾超前宣称、且专本科可做的缺口 | 未在本文立 ID 的全新行业域 / 新 DOM |
| 提到就挂、未提保持默认 | 真通道/硬件/模型类加价项 |

### 0.4b 一逻辑一写法 · 先复用现有结构 · **改原文件、禁止新建兼容层**

| 规则 | 含义 |
|------|------|
| **写前先搜** | 开写任一 E-* 前：搜基线 Store/Controller/Vue、`features/*`、`capabilities`、SQL fragment、相似 cap（如 `deadline`/`quota`/`stock_io`/`pass_code`/`guestbook`） |
| **有则改之** | 已有表/字段/API/组件能承载 → **直接改原文件扩展**（`hasCap` 分支、扫词挂载、列存在才读写），禁止再抄一套平行 Store/平行路由/平行状态机 |
| **工厂侧禁止新建「兼容文件」** | **不允许**为本次变更再新建 `*Compat*` / `*Legacy*` / `*V2*` / `*Adapter*` / `*Wrapper*`，或「新文件调用旧文件」的双轨；应 **改原来的** `features/*.py`、`capabilities.py`、Store、Controller、Vue、SQL fragment |
| **基线同样** | 学生骨架里能挂进现有 `TicketStore`/`OrderStore`/既有页面的，改原 Store/原 Vue；禁止 `TicketStoreRenew.java` 之类旁挂副本 |
| **何时才允许新文件** | 仅当现网**确实没有**可挂靠落点（无对应 Store/无对应 feature 模块）时，才新增**一个**正式落点文件，并在该 E-* 规格写明「搜过 X/Y/Z，均不可挂」；仍禁止再留旧实现并行 |
| **禁止双轨** | 同一业务语义不得两套写法并存；发现双轨须合并进原文件并删掉多余文件 |
| **学生包只见一条路** | README/菜单/按钮只描述这一条实现；禁止「亦可选用另一套」 |

### 0.5 兼容：整包仍是一个系统 · **不影响现有结构**

| 规则 | 含义 |
|------|------|
| **默认路径零回归** | 材料未扫到本批词时：菜单、表集合、状态机、按钮、种子、README 与**改前现网一致**（允许工厂内部注释/门禁增强，禁止改默认业务行为） |
| **只做加法** | 新 cap / 新表 / 新菜单 / 新状态 **仅**在扫词挂载后出现；禁止改写现有 Store 主路径语义来「顺带」塞新玩法 |
| **禁止拆壳** | 不新开物理骨架、不另起第二套 Ticket/Order、不把现有域拆成多 DOM；挂靠现有 `TicketStore` / `ArchiveStore` / `OrderStore` / `MessageStore` / `stock_io` |
| **状态机不打架** | 新状态（如 `waitlisted`）用可选列/可选枚举；未挂 cap 时转移表与今日相同，前端不出现新按钮 |
| **API 向后兼容** | 新接口可增；旧接口参数/返回字段不删不改义；新字段缺省与旧客户端兼容 |
| **SQL / 表预算** | 扫词才注入新表或 ALTER；未挂载包不得多表；叠加仍 ≤15 |
| **域默认能力表不动** | `DOMAIN_CAPABILITIES` **不**因本批给 LIBRARY/SHOP 等塞默认 cap；扫词结果写入本次 bake 的 caps 列表 |
| **出包** | 未扫词 bake 与现网主路径可回归；扫词 bake 主路径可点、门禁绿；旧题（图书/宿舍/实习）匹配与办理不红 |
| **禁止借重构** | 本批不做「顺便重构」基线目录、通用壳改名、大挪 Store；若某 E-* 必须动公共代码，只加分支（`if (hasCap)` / 列存在才读写），默认走旧逻辑 |

### 0.6 学生包：前后端实现必须一致

对学生 ZIP 而言，**同一 cap 的前后端同开同关、同语义**，禁止「有按钮无接口 / 有接口无页面 / 文案承诺与 API 行为不符」。

| 规则 | 含义 |
|------|------|
| **同挂同隐** | bake 未挂该 cap → 前端无菜单、无按钮、无路由占位；后端无对应 API 暴露或调用即明确业务错误且前端不可达 |
| **同挂同显** | bake 已挂该 cap → 前端可走完主路径，后端 Store/API/表/状态机齐全；禁止只加 FE 或只加 BE |
| **契约一致** | 字段名、状态枚举、按钮可用条件与后端校验一致（例：续借次数、候补晋升）；FE 不展示后端不接受的操作 |
| **说明书一致** | README / 论文系统实现 / 菜单名与实包前后端一致；禁止只写一端 |
| **门禁双边** | 扫词 bake 的 gate：断言 FE 路由/组件 + BE Store/API（或缺一即红）；未扫词：双边皆无 |

### 0.7 功能禁止薄实现（空壳 / 半截）

挂上的能力必须是**可答辩走完的完整闭环**，禁止「有入口无规则、有表无转移、只改文案假装有功能」。

| 禁止（薄） | 要求（厚够用） |
|------------|----------------|
| 只有菜单/按钮，点了 toast 或空页 | 用户端 + 管理端（若该能力需要审）都能走通主路径 |
| 只有字段展示，无写入/无校验 | 有持久化、有合法/非法用例（如续借超次拒绝、候补满员可排队） |
| 只有 README 一段话 | 与 Store/API/FE 一致且可点 |
| 状态写死一个、无转移 | 状态集合 + 合法转移 + 角色谁可点，与现网单据习惯一致 |
| 硬编码一条假数据当功能 | 种子可演示，但逻辑对任意符合条件的数据成立 |
| 「先占位后续补」进学生包 | 未做完不得挂 cap、不得写进密功能表「扫词开/已实现」 |

**厚度底线（每个 E-* 至少）**：扫词挂载 · 表或列（若需要）· BE 校验与状态 · FE 入口与反馈 · 未挂时完全不可见 · 至少 1 个正路径 + 1 个拒绝路径测试。

**一票否决（汇总）**

| 类 | 条件 → 不得标已齐 |
|----|-------------------|
| 结构 §0.5 | 未写该功能的旧开题主流程缺按钮 / 多空菜单 / 状态走不通 |
| 前后端 §0.6 | 扫词出包只能点 UI 却 404/空壳，或有 API 无入口，或两端状态语义不一致 |
| 双轨 §0.4b | 同语义两套 Store/路由/扣减逻辑并存；或新建 Compat/V2/Adapter 旁挂而不改原文件 |
| 薄实现 §0.7 | 有入口无闭环、无校验、无持久化、或仅文案占位 |

## 2. DOC-FIX：历史超前宣称 → 除 OOS 外全部落地

### 2.1 总原则（按你的口径）

1. **属于 `out_of_mvp` / §0.4 硬边界** → 密功能表改「不支持」+ 原因；代码不装能；匹配/QA 继续拒或双显。  
2. **其余凡文档/FAQ 写过、专本科做得出的** → **必须做**：材料提到就挂，未提保持域默认；落地后表写「扫词开」。  
3. **禁止**「只改文档删功能」来消超前宣称（OOS 除外）。  
4. **实现须嵌入现网一壳**：同一套登录/菜单/单据/消息/库存，出包可答辩，旧题兼容。  
5. **不影响现有结构**（§0.5）：未挂 cap 时零回归；只做加法；禁止拆壳、禁止借本批重构基线。  
6. **学生包前后端一致**（§0.6）：同挂同显、同隐同无；禁止单端空壳。  
7. **一逻辑一写法**（§0.4b）：写前搜现网；有则**改原文件**；禁止 Compat/V2/平行双轨。  
8. **禁止薄实现**（§0.7）：挂则闭环可答辩；禁止占位/半截。

## 3. 分项规格（实现契约）

每项交付必须同时具备：`capabilities`（或 schema 开关）· 扫词 · **后端** Store/API · **前端** 菜单/页面/按钮 · SQL/门禁 · 测试 · 密功能表一行 · **学生可见文案无「演示」** · **§0.6 前后端双边齐全** · **§0.7 非薄实现（闭环+校验）**。

### E-01 续借 `loan_renew`

| 项 | 约定 |
|----|------|
| **cap id** | `loan_renew` |
| **扫词** | 续借、延长借期、借期延长、renew（中文为主） |
| **行为** | 借出中（approved/overdue 可配）单据：用户申请续借 → 可选自动通过或待审；`due_at` 按配置延长 N 天；`renew_count` ≤ `maxRenew`（schema，默认 1） |
| **不做** | 跨馆互借、预约到书自动续 |
| **域** | 材料命中且域有 `deadline`+借还语义（LIBRARY/EQUIP 等）才挂 |
| **验收** | 未扫词：无续借按钮；扫词：我的借阅可续、超次拒绝；README 有一段；FAQ 仅挂载时写续借 |

### E-02 候补 `waitlist`

| 项 | 约定 |
|----|------|
| **cap id** | `waitlist` |
| **扫词** | 候补、等位、等待队列、满员候补 |
| **行为** | 名额满：可提交候补单（status=`waitlisted`）；有人取消/驳回回补名额时，按候补创建时间 FIFO 自动（或管理一键）晋升为正式占用；用户可取消候补 |

## 6. 验收（每项 E-* 打齐才标已齐）

1. **未扫词 bake**（同域对照开题）：无该 cap、无新表、无菜单/按钮、README 无该段；**主流程与改前一致**（§0.5）。  
2. **扫词 bake**：有表/API/菜单，主路径可点通；与原有借还/下单/报名等同一登录与菜单壳。  
3. **前后端一致**（§0.6）：FE 可达操作均有 BE；BE 能力均有 FE 入口；状态/次数等校验双边一致。  
4. **密功能表**状态为「扫词开」或「已实现」且与实包一致。  
5. **学生可见面**无「演示」业务措辞（H22）。  
6. **旧题回归**：图书 / 宿舍 / 实习（及本能力近邻域）匹配与主路径不红。  
7. **表预算**：扫词叠加后仍 ≤15（超则该 cap 复用已有表或文档标明互斥组合）。  
8. **结构未伤**：未改 `DOMAIN_CAPABILITIES` 域默认表；公共 Store 仅 `hasCap`/列存在分支，默认旧逻辑。  
9. **无双轨**（§0.4b）：同语义只有一条实现路径；写前已对照现有结构并复用、改原文件。  
10. **非薄实现**（§0.7）：正路径可走通 + 至少一条拒绝校验；非菜单占位。
