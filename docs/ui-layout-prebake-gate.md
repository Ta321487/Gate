# 起包前 UI 布局闸（活表）

> **本文只负责一件事**：**布局一眼病**——错位/挤破/叠穿/溢出等几何硬伤，如何在 bake 起包前用全表台账 + 门禁挡住（页 / 壳 / 组件）。  
> **不负责**：可交互控件「用哪种、下拉能不能手填」（[`form-controls.md`](./form-controls.md)）；68 域勾选结果台账（[`ui-domain-diagnosis.md`](./ui-domain-diagnosis.md)）；观感精美/换皮（观感批次 / 选型册）；出包预览容量；业务能力四件套。  
> **一句话**：本册定「乱不乱」的**规则与闸**；诊没诊过写在诊断表；控件对不对写在控件册。  
> **状态**：口径已立 · 代码未开。  
> **索引**：[README.md](./README.md) · [`../HANDOFF.md`](../HANDOFF.md)。

## 0. 问题与站队

| 现状 | 后果 |
|------|------|
| 布局病在 `skeletons/baseline` 的 Vue/CSS（**含 components / layouts**） | 改工厂就能种下；一处组件歪 = 多页同歪 |
| 护栏多为源码字符串 / 列契约（`test_*_look_polish`、`test_ticket_ui_columns` 等） | **测绿 ≠ 画面不歪、不挤、不破** |
| 发现环挂在「人 bake + 起预览」 | 老板不起包就骂不出来；助手闭眼改 UI |

**站队**：**修工厂**。禁止只擦某一学生 ZIP；洞进共享台账 + 自动检查。  
**目标**：改基线 UI 时就能因 **一眼病** 红；**起包不再是发现这类问题的第一环**。起包仍验业务闭环（菜单/写库/能力），不拿来当常态布局 QA。

### 0.0 答辩风险（为何必须严）

工具条歪了、按钮挤破卡片、字叠在按钮上、操作列撑爆表格——老师 **不用懂代码** 也能看出「这不像学生认真排过」。  
这类观感常被解读成模板拼装 / AI 生成痕迹，答辩风险高于「颜色不够好看」。  
因此本闸验的是 **人一眼能判有问题的控件几何与盒子纪律**，不是「路由能打开」、也不是「精美分」。  
**页面齐、组件漏 = 未尽责**；**只挡错位、不挡挤破/叠穿 = 未尽责**。

### 0.0a 「一眼病」范围（AI 常犯 · 本闸主责）

判定口诀：**正常人手写交作业前会改掉；AI/批量改皮常留下。**  
下列均为本闸缺陷类（`defect_class`）；发现新样例 → **24h 内补进本表**，再落结构/视觉断言。

| `defect_class` | 人一眼看到什么 | 典型成因（AI/批量） | 闸怎么挡（方向） |
|----------------|----------------|---------------------|------------------|
| `misaligned` | 按钮/标签和邻居对不齐、悬空、漂出槽位 | absolute/负 margin、漏对齐容器 | 几何：在槽内、基线对齐 |
| `crushed` | **按钮挤破**：控件被压扁、文字截断成「…」到不可读、主按钮高度塌掉 | flex 子项 `min-width:0` 滥用、父级定高过死、一排塞太多 `el-button` | 几何：可点区最小宽高；文案不全是 ellipsis 且不可读 |
| `overflow` | 按钮/芯片/工具条 **撑破**卡片、表格单元格、对话框；出现横向滚动条「长歪一截」 | `nowrap` + 无 wrap 策略、列宽写死、dialog 内容过宽 | 几何：子矩形 ⊆ 父内容盒（允许约定内滚动区） |
| `overlap` | 两控件 **叠穿**（字压按钮、状态压操作、浮层挡主 CTA） | 绝对定位叠层、z-index 乱、负 margin 抢位 | IoU/中心距；浮层不盖主 CTA |
| `wrap_mess` | 本该一排的操作 **碎成难看多行**，或状态+按钮缠成一团 | 无脑 `flex-wrap`、状态与操作同根 wrap | 结构禁同根；视觉：操作区行数/分区可读 |
| `gap_chaos` | 间距忽大忽小、两按钮贴死或中间空洞一块 | 混用 margin 与 gap、条件 `v-if` 留空槽 | 结构：统一 gap；视觉：相邻间距落在带宽内 |
| `column_blow` | 表格操作列 **撑爆**整表，或列宽把主信息挤没 | 行内一堆按钮横排、无 `fixed`/`min-width` 策略 | 行内操作独立列 + 上限；主列仍可见 |
| `chrome_break` | 顶栏/侧栏入口挤成两排乱麻、品牌与按钮抢行 | 菜单项过多仍全直出、壳未分岔 | 壳专用断言（可与既有顶栏规则对齐） |
| `clip_hide` | 主按钮/关键操作被 `overflow:hidden` **裁没**，或点得到区域在可见外 | 父级 hidden + 子项定位 | 主 CTA 在视口/容器可见盒内 |
| `hit_stack` | 可点区域 **重叠**导致误点（两个 button 热区交叉） | 透明叠层、扩大点击区写炸 | 交互热区 IoU 上限 |

**不进本闸（有别册）**：配色土、不像商业站、短签腔不对——归观感加厚；工厂腔文案——归学生可见文案规则；控件该用日期却用文本框——归表单控件规则。  
**灰度**：略挤但不影响认读/点击 → 可先记样例再收紧阈值；**已挤破 / 已叠穿 / 主按钮不可读** → 一律红，无灰度。

### 0.0b 案例草图（ASCII · 给人与 AI 对形）

约定：`[` `]` = 按钮/芯片；`|` = 容器边；`#` = 叠穿/挡死；`.` = 空洞；`~` = 被裁切。  
左 **病** / 右 **好**。草图不是像素真值，但是 **执行时的形状标准**：

| 草图纪律（硬） | 含义 |
|----------------|------|
| **「好」侧必须一眼整齐** | 左右边框对齐、同列左缘齐、同行按钮等高同隙；**禁止**「好」图画歪、长短参差当示范 |
| 「病」侧才允许歪/破/叠 | 用来对照，不是仿写目标 |
| 实现对齐「好」的几何关系 | 盒内、分行、均匀 gap、列宽可读——不是只抄文案语义 |

若某条「好」草图自己看起来就不齐 → **先改草图再写代码**（草图即验收样板）。

```
|   [详情]         |  ←缩进乱     | [详情] [收藏]    |  ←同一操作行

```

```
+------------------------+        +------------------------+
| [立即...][申..][..]    |        | [立即借阅]             |
| ▲ 全省略 / 高度塌半行  |        | [申请续借] [更多]      |

```

#### `overflow` 撑破容器（帽子比头大）

```
+-------------+  [备注][打印]--->       +-------------+

| [通过][驳回][转派]...                 | [通过][驳回]|

                                            每行两钮同宽同隙
```

（「好」侧两行都是「两钮 + 框内收口」，不要画成一长一短歪着收。）


#### `wrap_mess` 缠行乱麻（状态+按钮同一 wrap 团）

```
+---------------------------+     +---------------------------+

```

#### `gap_chaos` 间距失控（贴死或空洞）

```

```

### 0.1 尽责标准（硬）

| 算尽责 | 不算尽责 |
|--------|----------|
| 基线 **路由页 + layouts 壳 + components 共享件** 全表已生成，布局闸覆盖率 **= 100%** | 「代表页 / 热门页 / 先抽几页」或「组件跟宿主页捎带看一眼」冒充已齐 |
| 新增 `views` / `layouts` / `components` 下 `.vue`，或路由/菜单 path → **同批入台账**，否则门禁红 | 台账手写漏页/漏组件、靠人眼抽检补洞 |
| 同页多脸（`*_surface_style` 等）按 **路由 × 皮** 分行，行行有验 | 只验默认皮、漏其它 surface |
| 页内对话框/抽屉 + **独立 Dialog 组件** 均有行 | 只扫 path、弹层/共享对话框按钮错位漏网 |
| 改某一 `components/*.vue` → 重跑该组件行 **及** 台账登记的宿主页行 | 只测组件文件字符串、不看挂载后画面 |

**抽检漏一页或漏一个组件 = 布局闸未尽责。**  
允许「管道试点」先跑通 1～2 行，但**不得**在覆盖率未满时宣称布局闸已齐或收口。

## 1. 台账范围：「所有可见面」（不只页面）

学生 ZIP 会按能力剪枝，故台账真源是 **基线能进包、且学生/老师能看见的 UI 面**，不是某一张出包菜单。

| # | 层 | 真源路径 | 台账用途 |
|---|-----|----------|----------|
| A | 菜单可达 | `backend/app/bake/menu_routes.py` → `USER_MENU_PATHS` / `ADMIN_MENU_PATHS`（须与 `skeletons/baseline/frontend/src/utils/menuRoutes.js` 同表） | 角色菜单能点到的 path |
| B | 路由实挂 | `skeletons/baseline/frontend/src/router/index.js`（含各 `with*Routes`、staff、登录/注册等） | 有组件无菜单、有菜单无路由、壳外页 |
| C | 视图页 | `skeletons/baseline/frontend/src/views/**/*.vue` | 路由页 / 孤儿 Vue |
| D | 同页多脸 | bake 注入的 `*_surface_style` / `portalHomeStyle` / `cardVoice` 等 | **同一 path × 每种皮 = 多行** |
| E | **共享组件** | `skeletons/baseline/frontend/src/components/**/*.vue` | **每个 `.vue` 必须有台账行**；含按钮/工具条/弹层/浮层/壳附属操作的尤严 |
| F | **布局壳** | `skeletons/baseline/frontend/src/layouts/**/*.vue` | 顶栏/侧栏/登录壳上的入口与主按钮；与公共壳观感分家，本闸管 **一眼病**（§0.0a） |

量级参考（随仓库变，D1 以扫描为准）：`views` 一百多、`components` 约三十、`layouts` 若干——**不得因「组件多」改为抽检。**

### 1.1 行种类 `kind`

| `kind` | 含义 | 覆盖要求 |
|--------|------|----------|
| `page` | 路由页（C + A/B） | 打开 path；验 `layout_faces` |
| `shell` | 布局壳（F） | 在至少一条代表路由下验壳上控件；壳文件变更触发 |
| `component` | 共享组件（E） | **组件自身一行**；须列 `hosts`（引用它的 page/shell）；视觉验 = 在 hosts 上挂载态断言，或组件 story/夹具态——**禁止「无 hosts 的裸文件行」长期 pending** |
| `dialog` | 页内或独立对话框/抽屉 | 可挂在 page 下，或 `components/*Dialog*.vue` 独立 `component`+`dialog` 面 |

### 1.2 台账一行最少字段

| 字段 | 含义 |
|------|------|
| `row_id` | 稳定 id：`page:side:path[:surface]` / `shell:<file>` / `component:<file>` / `dialog:<file-or-suffix>` |
| `kind` | `page` / `shell` / `component` / `dialog` |
| `side` | `user` / `admin` / `staff` / `auth` / `public` / `shared`（组件跨端用 `shared`） |
| `path` | 页面必填；组件可空，但 `hosts` 必填 |
| `vue` | 相对 `frontend/src/` 的路径（`views/...` 或 `components/...` 或 `layouts/...`） |
| `hosts` | **`kind=component|dialog` 必填**：引用方 `row_id` 列表（由 import 图生成；手补禁止当常态） |
| `mount` | `always` 或 cap/traits/schema 条件（与 `effective_paths` 同口径） |
| `surfaces` | 无多脸则空；有则列出须循环的皮 id |
| `layout_faces` | `toolbar` / `row_actions` / `primary_cta` / `card_foot` / `dialog` / `chrome` / `float`（可多选） |
| `interactive` | `true` 若含可点按钮/链接式操作/开关主控；`false` 仅展示（仍须入账，结构契约可轻、视觉可只断言「未撑破宿主」——**不可删行**） |
| `gate_status` | `pending` / `structural_ok` / `visual_ok`（收口前：凡 `interactive=true` 必须 `visual_ok`） |

页内对话框：无独立文件时，`kind=dialog`，`vue` 仍写宿主，`row_id` 加后缀（如 `#apply-dialog`）。  
独立对话框组件（如 `TicketRateDialog.vue`、`OrderTraceDialog.vue`）：**以 `components` 文件为准入账**，不得只藏在宿主页子项里了事。

### 1.3 组件层硬规则

1. **`components/**/*.vue` 与 `layouts/**/*.vue` 全量入账**，与是否「热门」无关。  
2. 扫描 import：每个 component 行的 `hosts` 必须覆盖基线内全部引用方；新增引用未进 `hosts` → 红。  
3. 无引用的孤儿组件 → 红（删组件或挂回），禁止「先空着」。  
4. 浮层/全局件（如 `AiAssistantFloat`、`MessageBell`、`CartBadge`）`layout_faces` 含 `float`/`chrome`，须在壳或代表宿主上验位置（不挡主 CTA、不溢出视口）。  
5. 表单控件类（如 `ArchiveFieldControl`、`ProfileFieldInputs`）验：标签与控件对齐、主操作不与字段挤叠/挤破；控件选型对错仍归表单规则，本闸管 **§0.0a 几何一眼病**。

### 1.4 对账红灯（台账生成后立刻要有）

下列任一成立 → **台账门禁红**，不许靠「以后补」：

1. A 有 path，B 无对应路由（或反向：B 业务页不在 A 且未标 `auth`/`public`/`hub-only` 豁免表）
2. C/E/F 有 `.vue` 未出现在台账（**组件/壳与页面同一条红线**）
3. 台账有行，对应 `.vue` 或 path 已删
4. 已登记的 `surfaces` 集合与代码/选型真源漂移（缺皮或多皮）
5. `kind=component` 的 `hosts` 与 import 图不一致，或 `hosts` 为空
6. `interactive=true` 长期停在 `pending` 超过实现批次允许窗口（D4 收口前必须清零）

豁免须**显式表**（纯重定向壳、无模板的薄 re-export——若有）。**禁止**「组件太碎所以不验」类口头豁免。

## 3. 三层闸（起包前）

### 3.1 工序闸（规则层，可与代码同期生效）

动 `skeletons/baseline/frontend` 且触及布局（`views` / `layouts` / `components` 的模板、CSS、工具条/按钮区）时：

1. 收工前必须对照**台账中绑定该文件的全部行**（改组件则含其 `hosts` 页）看过画面或跑通对应冒烟；  
2. 仅 pytest 字符串绿 **不算**布局收工；  
3. 无活页（基线冒烟未起、无 fixture）→ 不得宣称观感/布局已齐；  
4. 只改 `components/`、不看宿主页画面 → **视为未验**。

落地形态：本册 +（后续）`.cursor/rules` / skill 补一句「改 UI 必对台账行（含组件）」；**不**替代 3.2/3.3 机器闸。

### 3.2 结构契约闸（便宜，挡重复坑）

对台账 `layout_faces` + §0.0a 做**源码或静态 DOM 契约**（扩现有 polish 测，禁止只断言「字符串存在」）：

| 模式 id | 主要挡 | 口径（示例，实现时钉成可红断言） |
|---------|--------|----------------------------------|
| `no_status_acts_same_wrap` | `wrap_mess` | 状态标签与操作按钮禁止挤在同一 `flex-wrap` 行 |
| `toolbar_layers` | `gap_chaos` / `wrap_mess` | 多段 `.toolbar` 须可区分间距/分区，禁止无间隔三坨堆叠 |
| `primary_cta_in_slot` | `misaligned` / `clip_hide` | 主 CTA 落在约定容器 class，禁止裸 `position:absolute` 漂出卡片 |
| `row_actions_column` | `column_blow` / `overlap` | 行内操作在独立列/actions 槽，不与状态 chip 同 flex 子树根 |
| `actions_may_wrap_or_menu` | `crushed` / `overflow` | 一排操作超过 N 个须允许换行分区或收进「更多」，禁止单行硬塞挤破 |
| `no_orphan_absolute_btn` | `misaligned` / `overlap` | 业务按钮禁止脱离文档流且无定位包含块 |
| `dialog_body_scroll` | `overflow` | 对话框超高走 body 滚动，禁止整页被 dialog 撑出横向滚动 |

新骂过的一眼病 → **先补 §0.0a `defect_class`（若新）+ 本表模式 id，再写测**；禁止只修当面页/组件。病在共享件 → 断言钉 `components/` 并扫全部 `hosts`。

### 3.3 视觉冒烟闸（主保险丝）

**不 bake 学生整题**，在基线上渲染台账全行：

1. **Fixture**：最小 `APP_DELIVERED`（或等价注入）+ 按 `mount` 打开所需 cap；多脸按 `surfaces` 循环。须覆盖「长标签 / 多按钮 / 窄宽」至少一种 **挤压场景**（短文案全绿不算验过挤破）。  
2. **运行**：`skeletons/baseline/frontend` + mock API / 静态夹具，能进对应用户端/管理端/员工端页。  
3. **断言（每行至少，映射 §0.0a）**：  
   - 非白屏；`layout_faces` 节点存在；  
   - **盒内**：关键按钮/芯片外包矩形 ⊆ 父内容盒（`overflow` / `crushed`）；  
   - **不叠穿**：与邻接关键控件 IoU 低于阈值（`overlap` / `hit_stack`）；  
   - **可点可读**：主 CTA 可见、高度/宽度不低于最小可点尺寸，关键文案不得整段变单一 ellipsis（`crushed` / `clip_hide`）；  
   - **壳**：顶栏关键操作不出现未约定的双行乱麻（`chrome_break`）。  
   `kind=component` 须在 `hosts` 挂载态（或专用夹具）下断言。  
4. **触发**：改 `views`/`layouts`/`components` → 重跑**该文件行 + 组件 hosts 行**；全量挂 `slow` 或夜间/手动全量。  
5. **覆盖率**：须视觉行 `visual_ok` = **100%** 才准称本层已齐；**页面满、组件未满 = 未齐**；**只验对齐不验挤破 = 未齐**。
