# 工厂可维护资产台（词表同构能力）

> **本文只负责**：描述一类**新功能方向**——工厂内维护结构化资产，bake / 门禁 / 控制台消费，少改学生 ZIP。  
> **不负责**：论文图几何（parked **m**）、题名库接线（**j**）、运营台产品化 UI（**p**）、Surface Lexicon 运维尾债（**e**）。那些是别的单。  
> **范本**：`factory_zh_lexicon` → bake `COMMENT` + 侧栏「词表维护」（2026-11-16）。  
> **状态**：方向册 · **未开工** · 见 [`parked-work.md`](./parked-work.md) 碎另案 **q**。  
> **口令**：`做资产台` / `做资产台 #n`（n 为本文选项编号）。  
> **索引**：[README.md](./README.md)

## 1. 范本解剖（词表 → COMMENT）

### 1.1 五段合同（新资产必须对齐）

| 段 | 词表怎么做的 | 新资产也要有 |
|----|--------------|--------------|
| **真源** | 库表 `factory_zh_lexicon`（kind/key/zh） | 工厂库或版本化 JSON，**不是**骨架里散落字符串 |
| **迁入** | 从 `er_zh` 首迁（一种子） | 从现有硬编码扫一遍进台，禁止双真源长期并存 |
| **注入** | bake `annotate_sql_comments`；图保存可回写 | bake 写 SQL / schema JSON / 菜单 / README 片段 |
| **维护面** | 控制台侧栏：列表 / 迁入 / 扫缺口 / 增改删 | 同级工具条能力；缺口可扫 |
| **闸** | 单测 + 可选出包对账 | 开了宣称 → 包内必须有；关了或未挂 → 不得残留 |

### 1.2 硬边界（学词表时一起学）

1. **改工厂，不改当面 ZIP** 消红。  
2. **所有修复针对全域全皮**：机制一套、各域填自己的键值；首刀可以先挂 1～2 域**验证合同**，收工前合同与闸必须能罩全族，禁止「只给 SHOP 开一张旁路表」或单域永久特例。  
3. **学生可见文案**走**本域业务角色**口吻（谁在用哪个端，就说谁会说的话）；工厂腔（开题、bake、DOM-*）不进包。口径真源：`.cursor/rules/student-copy.mdc`（「店员/买家」仅为交易域举例；**规则范围仍是全域**）。  
4. **LLM 可建议稿，不可当唯一真源**；可复现规则收进台 + 测。  
5. **未立项注入路径，不许开对外开关**（与 tech-stack / capability 纪律一致）。

> **口吻按域 ≠ 修复按域切开。** 租用域说「租用者」，交易域说「买家」——那是键值内容；表结构、bake、侧栏、闸是全厂一份。

### 1.3 判定「算不算同构」

同时满足才算本册范围的选项：

- 人工今天仍在**按包或按页**改同一类内容；  
- 内容能抽成 **(作用域, 键) → 值**；  
- bake 有明确落点（文件/列/JSON 键）；  
- 能写「扫缺口」：键在包里出现、台里没有 → 红。

不满足的（例如「把模块图拖好看」）不进本册主表，最多在 §6 一笔带过「别和本册混开」。

## 3. 选项 #1 · 状态机话术表（细案）

### 3.1 问题

同一状态码在列表、详情按钮、用户端进度、README 里各写各的；换域（租用/借阅/报修/订单）更容易串词或英文码露脸。

### 3.2 真源形状

```text
factory_status_copy
  domain_id   | 如 DOM-SHOP / * 表示跨域壳
  machine_id  | 如 order / ticket / borrow
  status_code | pending / paid / …
  label_zh    | 列表徽章
  action_zh   | 主按钮（可空）
  empty_zh    | 该态下列空时一句（可空）
  for_roles   | admin,staff,user 子集
  source      | migrated | scan | manual
```

### 3.3 迁入

- 从基线 Vue / `schema.labels` / 各域 soft 文案扫 `status` 字面量。  
- 与现有 `ticket_copy_text` / Surface Lexicon **分工**：本台管**状态码↔话术**；Surface 管分类轴、公告槽等页面 slot。禁止两处各维护「待支付」。

### 3.4 注入

- bake 写 `schema.statusCopy`（或并入现有 labels 树，但键合同固定）。  
- 基线组件只读 schema；禁止再写死中文状态名（闸扫）。

### 3.5 维护面

侧栏「状态话术」：按域筛选、扫缺口（包内出现的 status 无行）、批量迁入。

### 3.6 验收钉

- 单测：已知域至少 N 个 status 有中文；禁学生包硬编码表（抽若干路径）。  
- 出包可选：`p3` 类对账「menus/API 状态 ⊆ 台账」。

### 3.7 不做

- 不改状态机迁移边（谁能点谁）——那是能力/权限，另册。  
- 不靠 LLM 每包现场编状态名。

## 4. 选项 #2 · 字典 / 枚举值台（细案）

### 4.1 问题

分类、工单类型、优先级等：种子 SQL 一份、前端 `options` 一份、筛选又一份；控件闸禁止 `allow-create` 后，缺统一选项真源更痛。

### 4.2 真源形状

```text
factory_dict_values
  domain_id | skin_id? | dict_key | value_code | label_zh | sort | enabled
```

`dict_key` 例：`product_category`、`ticket_priority`、`refund_type`。

### 4.3 与控件闸关系

- 下拉 / 筛选 **只**消费本台（或本台 bake 出的 lookup）。  
- `filterable` 仍允许；`allow-create` 仍禁止。  
- `form-controls` 契约可增：基线里业务枚举必须来自 `dict:` 引用或 schema 注入块。

### 4.4 注入

- SQL：`INSERT` lookup / category 种子。  
- 前端：`schema.dicts[dict_key]`。  
- 管理端「分类维护」若已有页面：读同一 API 形状，避免第三真源。

### 4.5 扫缺口

- 开题或皮要求的分类名不在台 → 缺口。  
- 包内出现的 `value_code` 不在台 → 缺口。

### 4.6 首刀范围

先交易组 + 报修组各 1～2 个 `dict_key` 跑通，再全族扩。禁止一上来 68 域灌满空壳。

## 5. 选项 #3 · 演示剧本种子（细案）

### 5.1 问题

程序链通了，答辩仍空：仪表盘无单、用户端无可办事项、管理端无待办。种子散落在巨型 `domain_scene_seed.py`，人难维护「五分钟剧本」。

### 5.2 真源形状

```text
factory_demo_script
  domain_id | skin_id?
  script_id | 默认 default
  step_no   | 1..k
  role      | user/staff/admin
  title_zh  | 这一步叫什么（学生可见可进 README）
  need_rows | JSON：表 → 最少行数 / 关键状态
  seed_fragment_id | 指向可拼 SQL 片段或 cap ensure
```

另可有控制台只读「自检结果」不进 ZIP。

### 5.3 注入与自检

- bake：按 script 拼/点名已有 seed 片段，保证最少行。  
- 工厂预览或质检：「演示自检」跑 need_rows（可对预览库或对 SQL 静态断言）。  
- README：自动生成「建议演示顺序」小节（文案无工厂腔）。

### 5.4 与工作台种子债关系

历史上「工作台空图」类问题（parked **i** 已修）证明：**种子充分度是功能，不是单包补丁**。本选项把「充分度」升成可维护剧本，而不是再堆 `_SEEDS` 魔法字符串。

### 5.5 不做

- 不替代 Playwright 全站点点点（那是验收自动化，可另立）；本台保证**数据前提**。  
- 不发明开题没要求的营销链路。

## 6. 其余选项（排期级）

### 6.1 #4 字段控件语义台

把 `archiveFieldWidget` 的映射升到可维护台 + 扫「日期列仍用 el-input」。与 [`form-controls.md`](./form-controls.md) 同一语义表；本台是维护面，细则册仍是口径真源。

### 6.2 #5 岗位 × 菜单矩阵台

可视化勾选 `role × menu`，bake 生成 menus；扫「能力开了菜单无入口」。注意与 X-ORG 岗位菜单能力对齐，勿第二套 RBAC。

### 6.3 #6 API / 错误码中文台

`FACTORY_UI_FORBIDDEN` 管工厂腔；本台管**业务错误码**学生句。Java `MessageSource` 或统一 JSON 注入。

### 6.4 #7 业务规则参数台

超时天数、预约提前量、积分倍率等：开题扫词命中则台里要有默认值且写入包；宣称「支持超时」则门禁查数列/配置。

### 6.5 #8 表关系叙事句

补在 `er_zh` 旁：边不只几何，还有一句人话。服务论文「数据库设计」，不替代结构对账。

### 6.6 #9 测试账号卡

每域固定演示账号与三步；与 #3 剧本角色列对齐。

### 6.7 #10 开题 → 开关建议卡

匹配确认页：证据列表 + 建议 addons；人工勾选落确认。低置信仍走「已人工核域」。**不是**自动改开题。

### 6.8 #11 论文图题模板

`diagram_kind × domain` → 标准图题；与 Overrides / 出图管线对接。几何仍归 parked **m**。

### 6.9 #12 能力岛说明卡

每个 `cap` 一段学生 README + 菜单入口 id；`addons.X=true` ⇒ 说明与入口必在；`false` ⇒ 必不在。对假宣称闸是正向补全。

## 7. 建议落地顺序

```text
波次 A（先证明同构可复制）
  #1 状态机话术表  →  一个单据域跑通五段合同
  #2 字典台        →  同一域 1 个 dict_key + 控件闸钉子

波次 B（直接降跟单）
  #3 演示剧本种子  →  交易 + 报修各一条 default 剧本 + 自检

波次 C（匹配 / 诚实交付）
  #10 开关建议卡  ·  #12 能力说明卡  ·  #6 错误码中文

波次 D（材料与控件加固）
  #4 控件语义  ·  #5 菜单矩阵  ·  #7 规则参数  ·  #8 #9 #11
```

每波次收工标准：五段合同齐 + 对口 pytest 绿 + HANDOFF 记一笔；**禁止**只写文档勾已齐。
