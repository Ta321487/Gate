# 质检交付 · 诊断编排（只诊断、不改代码）

> **本文只负责**：把机器状态编成运营可读的诊断（「这怎么个事儿 / 下一步干什么」）；**完整诊断小卡的家在第六步「质检交付」**；规定前五步轻条 vs 第六步小卡、厂 LLM / 闸 / 编排分工。  
> **不负责**：改 bake、擦学生 ZIP、Cursor 修工厂工序（修仍找人 / Cursor）。  
> **站队**：程序归工厂；本册是**呈现与编排**，不是新闸。  
> **索引**：[README.md](./README.md) · 失败码 [bake-fail-analysis.md](./bake-fail-analysis.md) · LLM [llm-determinism.md](./llm-determinism.md) · 阶段轨 B1 · 就绪 `deliveryReadiness.js`

## 0. 家在哪：第六步交付区（先钉死）

阶段轨（产品顺序）：

`1 材料 → 2 匹配 → 3 生成 → 4 论文材料 → 5 答辩 PPT → 6 质检交付`

| | **完整诊断小卡**（总判 + 分层行头 + 下一步 + 链下方账本） | **轻条**（一行原因 + 一个主动作） |
|--|--|--|
| **出现位置** | **仅第 6 步** · `ArtifactsTab` pane=`delivery` · 工作台内（替换旧阻断卡） | 第 1～5 步各自主内容区顶 / 或详情壳就绪条一句 |
| **为何** | 门禁、验收、复审、重打包、QA 都发生在这里；小卡与下方折叠账本同屏才有搭配意义 | 前五步各有本职；塞完整小卡 = 位置错、观感怪、和第六步重复 |

样稿若画成「无阶段轨的孤立黄卡」会显得悬空——**必须以第六步交付区为宿主**。

### 0.1 前面五步怎么办

同一套「三问」语义，**换皮不换家**：

| 步 | 本职卡住时 | 诊断形态 | 典型下一步 |
|----|------------|----------|------------|
| 1 材料 | 缺开题/解析失败 | 轻条 | 补材料 / 重传 |
| 2 匹配 | 未确认、双显、拒收 | 轻条（匹配页内） | 确认匹配 / 看双显说明 |
| 3 生成 | Job 红、编译/填岛失败 | **轻条 + 失败码**（生成页）；详落点去失败分析 | 打开失败分析 · 修工厂后重新生成 |
| 4 论文材料 | 图红、手调闸 | 轻条（材料卡/图旁） | 强刷图 / 改手调 / 回生成 |
| 5 答辩 PPT | 导出失败 | 轻条 | 重跑 PPT / 看任务 |
| **6 质检交付** | 门禁/QA/复审/stale | **完整小卡** + 下方账本 | 验收 / 复审·改工厂 / 重打包 |

**跨步指引**：前五步若根因其实在门禁/包洁净（人还没进第 6 步），轻条写清并给 **「去质检交付」**，**禁止**在第 3 步生成页展开 p3q/p3lean 分层墙。

就绪条（壳顶）全程可显示相位名与主按钮；**分层诊断正文只在第 6 步展开**。

## 1. 产品口径（一句话）

在**第 6 步质检交付**，运营卡住时应看到完整人话小卡，而不是门禁名墙。  
前五步用轻条把人留在本步或送去第 6 步 / 失败分析。  
**挡下载只是第 6 步后果之一**，不是整条产品的标题。

厂侧 LLM **只诊断、不改代码**；修工厂落点给人 / Cursor，对齐失败分析 A 档。

### 1.1 诊断要回答的三问

1. **现在卡在哪一层 / 哪一步？**  
2. **机器已经知道什么？**  
3. **人下一步点哪？**（含：留在本步 · 去第 6 步 · 去失败分析）

## 2. 第 6 步内触发面（完整小卡）

下列入口共用**同一小卡合同**，宿主都是交付工作台：

| 触发面 | 运营在干什么 | 机器信号（例） |
|--------|--------------|----------------|
| **就绪条（壳）** | 扫相位 | `deliveryReadiness`；点进第 6 步才见分层正文 |
| **门禁未过** | 看分数、挡包 pill | `blocking_gates`、`p3q` / `p3lean` / … |
| **质量摘要** | 验收或点「质量摘要」 | `last_qa.findings` |
| **复审 / 验收** | 回退、偏差、毒区 | `regressions` / `fix_notes` |
| **工程已变更** | ZIP 不同步 | `zip_stale` |
| **已可交** | 绿了确认一下 | 短确认卡（无分层墙） |

第 3 步「生成失败」→ **轻条**（见 §0.1），不是完整小卡；D2 可把轻条与失败分析 A 档链齐，仍不挪宿主到第 6 步以外。

原则：**红要说清；绿要确认短。**

## 3. 分层模型（叠在一起时必须拆开写）

下载挡只是多层同时亮的一种表现。分层对**所有触发面**通用：

| 层 | 典型文案 | 机器真源 | 运营要听懂的话 |
|----|----------|----------|----------------|
| **流程** | 工程已变更 · 复审中 · 待重打包 · 生成中 | `zip_stale` / review.status / Job step | 还没轮到「内容好不好」，先走完相位 |
| **生成/编译失败** | Job failed · 骨架不完整 · 编译失败 | `error_code`（`BUILD_*` / `BAKE_*` / …） | 包没出来或半截；先看失败分析落点 |
| **内容审** | 交付质量摘要 · 学生可见文案 · 语义 | `p3q` / `p3copy` / `p3s` + QA findings | 串台、假宣称、工厂腔等 |
| **包洁净 / 结构** | 瘦身 · 布局 · 控件 · 主流程 E2E | `p3lean` / `p3layout` / `p3controls` / `p2`… | 盘上残留、一眼病、控件、路径 |
| **复审账** | 清单回退 · 未结案偏差 | `regressions` / `fix_notes` | 曾经绿过又退；或人登的洞未结 |

清单 32/32 与门禁 16/18 **可以同时成立**：台账齐 ≠ 相位可交 ≠ 「我听懂了」。

### 3.1 第 6 步内：与下方分区怎么搭配（防顶卡撑墙）

宿主：`ArtifactsTab` · pane=`delivery` · `DeliveryReviewPane` 一带。  
现页已是：**短阻断面 + 门禁全文弹层 + 复审明细折叠**。诊断卡**替换**旧阻断三点预览，**不**再叠一块长文；**不**出现在 1～5 步主区。

| 区位 | 职责 | 高度/内容预算 |
|------|------|----------------|
| **⓪ 阶段轨** | 当前高亮「6 质检交付」 | 壳级；小卡不重复画轨 |
| **① 就绪条** | 相位名 + 分数 pill + 主按钮 | 一行；壳顶可全局有，分层正文仍只在本步 |
| **② 诊断卡（交付区首屏）** | 总判 + **每层一行头** + 下一步 | **约 5～7 行**；默认不展开 finding 全文 |
| **③ 层内展开（可选）** | 点某一层 → 码 + 一句 + A 档链 | 同时只开一层；或门禁弹层 |
| **④ 下方折叠账本** | 待收敛、门禁名录、QA 全文、审计 | **默认折起**；顶卡可跳转高亮 |

**硬规矩**

1. 顶卡**不复制**下方 list；下方**不重复**总判句。  
2. 旧阻断卡与诊断卡**二选一**（替换），禁止「诊断卡 + 旧阻断卡」双墙。  
3. 审计勾选、已通过清单长表 → 永不进顶卡。  
4. 绿短确认（可交）更短：一句 + 下载，无分层墙。

样稿：[`mocks/delivery-diagnosis-card-preview.html`](./mocks/delivery-diagnosis-card-preview.html)（点「内容审」可跳到下方 QA）。

## 4. 诊断小卡合同（目标形态）

首屏卡字段（短）；详情在 §3.1 ③④：

| 字段 | 首屏 | 展开 / 下方 |
|------|------|-------------|
| **总判** | 必有 · ≤2 行（禁下载中心主义起句） | — |
| **相位** | 可并进就绪条；卡内可省略 | — |
| **分层行头** | 红层各一行：标签 + 半句 | 点开：码、一句说明、A 档链 |
| **finding 全文** | 不上首屏 | QA 折叠区 / 门禁弹层 |
| **失败码 / A 档** | 展开层内一行链 | 失败分析页 |
| **下一步** | 一行 + 与就绪条同权主按钮 | — |

**不做**：自动改仓库、自动擦 ZIP、小卡「一键修」、再调一轮 LLM 聊天当主解释、顶卡贴满 findings。

### 4.1 总判句式（禁止下载中心主义）

| 场景 | 总判应像 | 总判不要像 |
|------|----------|------------|
| 仅流程 stale | 「工程已变，验收通过后重打包即可」 | 「质量未过所以不能下」 |
| 门禁 + stale | 「两道门禁未过，且 ZIP 已过期；先消红再验收重打包」 | 只喊「暂不可下载」三条并列无分层 |
| 生成失败 | 「生成停在编译/填岛：码 XXX，落点 …」 | 「暂不可下载 ZIP」 |
| QA 仅 info | 「摘要有提示、未挡包；可交或按提示改皮」 | 当成挡下载红灯 |

## 5. 厂 LLM vs 确定性闸 vs 编排

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| **结构闸** | 穷尽已能判定项；关 Key 也不得假绿 | 代替人话编排 |
| **QA LLM** | 补结构闸缺口；输出 findings | 改代码；当唯一保险丝；写「建议优化」散文 |
| **失败分析 B 档** | DeepSeek 修法草稿，标未核对 | 直接当排修依据 |
| **编排层**（本册） | 把 phase + gates + QA + error_code + 码表**确定性拼接**成小卡 | 再喂大模型「解释一下页面」当主路径 |

硬原则：[`llm-determinism.md`](./llm-determinism.md)。

### 已知呈现坑

| 坑 | 现象 | 处置 |
|----|------|------|
| **下载中心主义** | 所有文案以「不可下载」起句，掩盖真实层 | §4.1；总判先分层再提下载后果 |
| **ok 与挡包打架** | `last_qa.ok=true` 但 `p3q` 因 warn 红 | 以 **gates.p3q.ok** 为准；注明 warn 挡包 |
| **只露门禁名** | 「门禁未过：交付质量摘要」无 finding | 必出 label + 首条人话 |
| **落点断裂** | 失败分析有 A 档，质检/复审未挂 | 键 → code → `fix_locus` 只读链 |
| **相位与门禁两套话** | 就绪条一句、复审区另一句、互相矛盾 | 同源 `buildDeliveryReadiness` + 同一小卡字段 |
| **未进复审却推结束** | 顶栏「进入复审」+ 卡上「结束复审并重生」对打 | `reviewActive` 决定 CTA：`start` vs `close-rebake`；卡上主 CTA 时顶栏不再重复同名主钮 |
